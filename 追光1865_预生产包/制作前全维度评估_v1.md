# 《追光1865》制作前全维度评估 v1

> 评估对象：v5 大纲（含玩法定版 v1.0）+ GDD执行案_v1 + 剧情人物细化包_v1 + UI设计文档_v1 + 已产 26 张图
> 评估维度：可行性 / 可玩性 / 故事性 / 技术插件
> 结论：**可做，但必须先做垂直切片（雾都章），全量六章以试玩数据为闸门。**

---

## 一、可行性

### 1.1 规模账（个人开发者）

| 项 | 数量 | 单件估算 | 合计 |
|---|---|---|---|
| 谜题 | 6 章 × ≈11 = 66 | 0.5–1.5 人日 | 50–90 人日 |
| 武戏 | 8 场 | 2–3 人日 | 16–24 人日 |
| 场景底（可进入剧照） | 约 40–55 张 | 出图+修图 0.5 人日 | 25–35 人日 |
| 立绘/情境人物 | 4 主角 × 3–5 套 | 0.5 人日/套 | 8–12 人日 |
| 系统（校图/显影/裁定/图鉴/存档） | 5 套 | 5–8 人日 | 25–40 人日 |
| UI 落地 + 演出 + 音频接入 | — | — | 20–30 人日 |
| 测试/打包/合规材料 | — | — | 15–25 人日 |

**总计约 160–250 人日**（不含剧本写作与美术返工）。个人全职 ≈ 8–12 个月；业余 ≈ 18–24 个月。
→ **结论：全量六章一次性开发不可行；必须"雾都章垂直切片 → 试玩节验证 → 再滚动后续章"。**

### 1.2 硬缺口（会直接卡住发布）

| 缺口 | 影响 | 何时必须解决 |
|---|---|---|
| JDK 17 + Android SDK + Godot Android 导出模板 | 打不出 TapTap APK | 试玩节报名前 |
| TapTap 开发者资质 + ICP 备案辅助证明 | 无法上架/试玩 | 提前 1 个月 |
| 软著 + 出版单位（版号路径） | 无法付费/内购 | 试玩验证后 |
| 商用音频（SFX/BGM） | 无声音=体验残缺 | Demo 前 |
| 字体 | 已锁 OFL（思源宋体/黑体 + IM Fell English） | 已解决 |

### 1.3 美术管线风险

- Agnes i2i 队列拥堵是**常态**（本次 10 张图 i2i 单张最多重试 14 次）。→ 已建立 `_prod.js` 批量重试管线；后续每章出图按"批量过夜跑"排期，不占白天开发时间。
- 角色一致性靠 i2i 锁脸 + 情境换装，已验证 4 主角；但**同角色多姿态仍需逐张验脸**，返工率按 20% 计。
- 结论：美术不是瓶颈，是**排期问题**；每章预留 1 周纯出图窗口。

## 二、可玩性

### 2.1 强项（差异化成立）

1. **校图（透光台叠图）**：触屏上"两张图对不齐"的手感是稀缺体验，且天然适配伪纪录片主题。
2. **三声裁定**：证据 / 编者按 / 异议卡三方对峙，把"判断"变成可玩动作，而不是读文本。
3. **E 完整度调色盘**：饱和度=证据完整度，盖章回色——**全游最强 juice 时刻**，且是叙事隐喻。
4. **每张剧照可进入**：拒绝了"影像小说"陷阱，场景即关卡。

### 2.2 风险与修法（按严重度排序）

| # | 风险 | 说明 | 修法（已纳入执行案 v2） |
|---|---|---|---|
| R1 | **竖屏 × 21:9 武戏冲突** | 9:16 竖屏里放 21:9 letterbox，动作区只剩约 1/3 高度，看不清 | 武戏改**竖屏构图**：上下窄黑边（约 8%），动作纵向排布；QTE 节奏点放屏幕下 1/3 |
| R2 | **三声裁定无失败=无张力** | 30 秒拖卡盖章，盖错也没后果，三章后变形式 | ①裁定全记录，终章听证会引用；②错盖→该卷饱和度暂时回落 10%，可用新证据补回；③异议卡翻面=真线索，不翻=少一档入口 |
| R3 | **校图重复疲劳** | 每章 2–3 次+终审，全游约 20 次同动作 | 每章只引入**一种新语法**（对齐/配重/透视/时序/负空间），旧语法只做组合；单章校图 ≤3 次 |
| R4 | **热点寻物挫败** | painted 背景里找小物件，移动端易烦 | 闲置 20 秒热区脉冲加强；错 3 次雷恩红笔提示；关键物件必有环境光引导 |
| R5 | **序卷教程过密** | P0 武戏 + P1 实物 + P2 校图 + P3 显影 + P4 三声，前 30 分钟五种新东西 | P4 改为**可选旁听**，不阻塞主线；三声裁定在卷二首次强制 |
| R6 | **中段节奏塌陷（卷七）** | 火星线主题强、事件弱，玩家目标感下降 | 卷七压缩为**半章**（5–6 谜题），与卷八合并为"一瞬"章内两档 |
| R7 | **文本密度** | 档案弹窗 ≤150 字已定，但 66 档累计仍大 | 关键信息必须**同时**出现在画面/道具上；纯文本只做补充；五声规则（≤3 句）严格执行 |
| R8 | **无重玩价值** | 线性叙事、无失败 | 假说卡/器物图版/评级履历做收集；终章按玩家裁定历史给不同听证会质询文本（非分支结局，是**措辞差异**） |

### 2.3 可玩性结论

核心循环成立，**R1/R2 必须在 Demo 前改掉**，否则试玩口碑会直接崩在这两点。其余为打磨项。

## 三、故事性

### 3.1 强项

- **真实事件嵌套**：1865 人类学学会分裂 → 萨加尔号 → 苏伊士通航 → 施利曼 → 玛丽·赛勒斯特 → 喀拉喀托 → 伦琴 X 光，链条真实可查，伪纪录片可信度极高。
- **四主角各有一条"谎"**：亚瑟"记录不会撒谎"／萧"世界会承认武"／沈"账本最诚实"／伊莎贝拉"我拍下的就是真的"——四条弧光都指向同一个主题：**证据不等于真相**。
- **雷恩是校正器不是反派**（火星线他对、土丘线他错），避免脸谱化。
- **玛乌娜之死**（录音当夜）与终章"雷恩空椅"是两个高浓度情感爆点。

### 3.2 风险与修法

| # | 风险 | 修法 |
|---|---|---|
| S1 | 沈清荷"海外执业"后可能游离主线 | **回购基金=清除者洗钱通道**：她管的账就是阴谋的资金面，职业位置把她钉进主线（positional revelation） |
| S2 | 玛乌娜易滑向"神奇原住民"刻板印象 | 给她**主动策略**：前期口述故意矛盾，是在保护岛上坐标；她不是记忆容器，是知情者与守门人 |
| S3 | 雷恩 1904 年死、终章空椅，玩家可能无感 | 卷四、卷七、卷十各给一次"他是对的/他错了"的实证时刻；终章前加一段他的最后一封投书全文（≤120 字） |
| S4 | 判无司/清除者揭示依赖 1884"判无"悖论，理解门槛高 | 卷三造纸坊、卷五缺失仪器、卷八电报簿三处递进铺垫；终章用**一页图示**把"同一坐标、两种判无"讲清 |
| S5 | 结局"悬置"可能被读成烂尾 | 终章明确结算：**3 条已证事实 + 3 条永久未知**，逐条上屏；未知不是没做完，是设计 |
| S6 | 真实人物被虚构言行，伦理/名誉风险 | 已定"史实核验声明"；追加红线：**不给真实人物虚构罪行**，争议言行只引用有据可查的公开立场 |

### 3.3 故事性结论

结构扎实，主题统一。**S1/S2 是正典级修补，必须在写第一章谜题表前定稿**（本评估已给出方案，默认采纳，可在谜题表中直接执行）。

## 四、插件与工具核查（GitHub / 官方源，2026-10-19）

| 需求 | 结论 | 采用 |
|---|---|---|
| 单元测试 | GUT（bitwes/Gut），有 godot_4_7 分支 | ✅ Step 2 接入 |
| 对话系统 | nathanhoad/godot_dialogue_manager（v3.10 支持 4.6）；本项目**无分支对话**（红线），短句用 CSV/JSON 即可 | ❌ 不引入 |
| CI 导出 | barichello/godot-ci Docker（需 4.7.2 对应镜像）；GitHub Actions | ⏳ 试玩节前接入 |
| Steam | GodotSteam GDExtension（已迁 **Codeberg**，非 GitHub），4.4+ | ⏳ Steam 阶段 |
| TapTap SDK | **官方仅 Unity / UE / Android / iOS 原生，无 Godot 插件** | ⚠️ 需自写 Android AAR 桥（Godot Android Plugin v2）或原生层包壳；排试玩节前 |
| Godot Git 插件 | godotengine/godot-git-plugin（官方，编辑器内 git） | 可选，不装 |
| Godot MCP | 社区有（dsh-godot-tool 等），非必需 | ❌ 不引入 |

**TapTap 结论**：先做**纯离线 APK**（试玩不需要登录/支付），把 TapTap SDK 与实名/防沉迷放到"预约页→正式上线"阶段再接，避免早期被原生桥卡死。
